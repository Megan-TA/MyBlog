# V8 中的 Event Loop

1. V8引擎只在一条主线程上跑JS，即单线程运行 JS；
2. 将 同步任务（如script代码、setTimeout/setInterval、setImmedidate、I/O、UI渲染）等任务放到宏任务队列；
3. 将异步任务（如Promise.then/catch/finally、MutatiobnObserver、QueueMicrotask、Node 的Process.nextTick（优先级比 Promise 高）放在微任务队列；
4. 从「宏任务队列」中依次取出任务执行，执行完后从「微任务队列」依次取出任务执行；
5. 浏览器执行渲染步骤，执行如样式计算、重绘、requestAnimationFrame 回调；
6. 重复上述步骤，无限循环；


# 浏览器缓存

浏览器缓存主要存放在两个位置
- Memory Cache
- Disk Cache

浏览器缓存分为 强缓存 和 协商缓存

1. 客户端先根据资源的http header判断是否命中强缓存，如果命中直接从缓存中读取；

2. 强缓存未命中，客户端发出请求，服务端根据请求的request header验证资源是否命中协商缓存，这个过程成为http再验证。如果命中，服务器将请求返回，状态码304，但不返回资源，而是告诉客服端可以从缓存读取；

3. 当协商缓存也没有命中，直接服务端返回资源给客户端；


强缓存

1. Expires 代表缓存过期时间；

2. Cache-Control： max-age  代表缓存最大生命周期；

协商缓存

1. Last-Modified 代表资源最后更新时间；

2. If-Modified-Since 代表 判断两次请求之间是否有过修改 没有直接返回协商缓存；


Cache-Control: no-store     // 永远不重用的“裸奔”模式
Cache-Control: no-cache     // 强制走协商缓存（不是“不缓存”）
Cache-Control: must-revalidate // 过期后必须问服务器，不能用本地副本
Cache-Control: private      // 仅浏览器可存，代理/CDN 不存
Cache-Control: public       // 允许代理/CDN 缓存（默认同域即可）



# 跨域

仅客户端上 域名、端口、协议 三者有一个不一样就会跨域。

跨域的办法

1. 服务端配置CORS

```nginx
access-control-allow-method
access-control-allow-origin
```

2.  Nginx 反向代理

```nginx
location / {  
    proxy_pass xxxxxxx;   
}
```

3. JSONP

   通过 js 标签引入一个 js 文件 这个 js 文件载入成功之后会执行我们在 url 参数中指定的函数 并且会将后端传入给我们的 json 数据作为参数传入

   例如：url?item=1&callback=filter

   原生 js 实现 jsonp 的话 定义好 callback 的函数名称,动态创建 js 标签 url 加上查询的参数写好 callback 的回调函数名称即可

4. 利用 iframe 并修改 document.domain 来跨子域

两个不同域的页面引入 iframe 标签 同时将两个页面的主域设置成相同的域名

# V8架构说明


解析 → 解释 → 优化 → 回收。

V8 架构 = Parser 预解析省启动 + Ignition 统一字节码 + TurboFan 热点优化 + Orinoco 并行 GC；
后台多线程编译/回收，主线程单线执行 JS，Isolate 隔离保障并行安全。


1. Parser（词法+语法）
    
- 统一入口，所有函数无论是否调用都先转 AST；
- 自带 预解析（PreParser） 机制：首次只扫“函数签名+词法声明”，遇到真正调用再二次完整解析 → 节省 30%+ 启动时间。

2. Ignition 解释器

- 2016 引入，统一字节码替代早期 Full-Codegen 直接生成机器码的旧架构；
- 字节码 = 寄存器+栈混合指令集（如 Ldar a0, Add a1, Return）；
- 解释执行时同步收集 类型反馈（Feedback Vector），为 TurboFan 提供投机依据。

3. TurboFan 优化编译器

- Sea-of-Nodes IR + 类型反馈 → 生成高度特化的机器码；
- 触发阈值：函数被调用 ≈ 10 次或循环回边 ≈ 1 万次；
- 关键特性：去优化（Deoptimization）——类型一旦变化，立即回退到字节码，保证正确性。

4. Orinoco 垃圾回收器

- 分代+并行+并发：

    新生代：半空间复制（Scavenge），16 MB × 2（64-bit）；
    
    老生代：Mark-Compact/Sweep，与主线程并发标记，并行压缩；
    
- 写屏障 + 记忆集，保证并发标记安全。

```
源码
 ↓  Parser（+Scanner） ①
AST
 ↓  Ignition 解释器 ②
字节码（Bytecode） ←→ 类型反馈（Feedback Vector）
 ↓  热点检测
TurboFan 优化编译器 ③ → 去优化（Deopt）→ 回退字节码
 ↓
机器码 → CPU 执行
        ↑
Orinoco 垃圾回收器 ④（并行+并发）
```
